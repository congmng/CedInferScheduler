# 异构环境实际验证报告

## 1. 验证范围

本轮尚未把 `10.70.251.47:2222` 纳入 GPU 实验：该节点此前已确认 8 张 A100 可用，但当前 SSH 认证失败，无法完成服务部署和实验接入。

## 2. 在线数据集

数据源为 Hugging Face 公开数据集 [`shibing624/sharegpt_gpt4`](https://huggingface.co/datasets/shibing624/sharegpt_gpt4)，文件为 `sharegpt_gpt4.jsonl`。由于当前网络代理的证书链限制，使用 HTTPS `-k` 下载文件头部，再截取完整 JSONL 行；共取 331 条源会话行，经过 Qwen3 tokenizer 和长度过滤后生成 16 条严格回放请求。

生成 workload：

```bash
python3 -m workloads.generators sharegpt \
  --model /mnt/home/model/Models/Qwen3-30B-A3B \
  --source bench/results/datasets/sharegpt_gpt4.sample.jsonl \
  --num-reqs 16 --sps 2 --seed 42 \
  --min-input-toks 128 --min-output-toks 128 \
  --output workloads/sharegpt-online-qwen3-30b-16-sps2.jsonl
```

提交到仓库的 workload 为 `workloads/sharegpt-online-qwen3-30b-16-sps2.jsonl`，SHA-256 为 `30badf5b278cf084ceeee55d8fa03854debe12f756e42f8af424bcd85f59656a`。

## 3. 真实 vLLM 运行

运行节点使用已有 `vllm/vllm-openai:latest` Docker 镜像，容器内版本为 `vLLM 0.27.1`、`torch 2.13.0+cu130`，使用本地 57G Qwen3-30B-A3B 权重，TP=4，`bfloat16`，`max_model_len=4096`，`max_num_seqs=8`，`max_num_batched_tokens=4096`。

```bash
python3 -m bench run \
  --model /mnt/home/model/Models/Qwen3-30B-A3B \
  --dataset workloads/sharegpt-online-qwen3-30b-16-sps2.jsonl \
  --output-dir bench/results/20260909-qwen3-30b-online \
  --tensor-parallel-size 4 --max-num-seqs 8 \
  --max-num-batched-tokens 4096 --max-model-len 4096 \
  --dtype bfloat16 --num-reqs 16
```

结果：模型启动耗时约 `86.2 s`，16 个请求全部完成，提交和执行阶段耗时约 `14.9 s`。真实 vLLM 观测到平均 latency `6491.9 ms`、P95 `8509.2 ms`，平均 TPOT `11.3 ms`。

同一 workload 随后在 `buaa@10.212.70.196` 的 4×RTX 5090 上运行，使用 `/data/Models/Qwen3-30B-A3B` 只读权重挂载。该节点 Docker 的 `--gpus all` 会漏注入一张卡，经 `nvidia-container-cli` 和显式设备列表核验后，使用 `--gpus '"device=0,1,2,3"'` 完成 TP=4 运行。真实 vLLM 观测到平均 latency `8995.9 ms`、P95 `16970.7 ms`，平均 TPOT `9.7 ms`；4 卡显存均约 `30544 MiB`，模型成功加载。

5090 的平均 TPOT 比 4090 低约 `14.1%`，但本次 P95 TTFT 为 `13106.7 ms`，高于 4090 的 `3434.1 ms`。该差异受请求到达、首次启动、并行调度和运行时状态影响，当前样本量不足以宣称 5090 在所有指标上优于 4090；后续应进行多轮 warm-up 后重复实验并报告置信区间。

为补充 3090 硬件点，在 `buaa@10.212.70.38` 的可用单卡 RTX 3090 上运行了同源 ShareGPT 数据、但使用本地 Qwen2.5-3B 权重 `/data/model/Qwen2.5-3B`。16 个请求全部完成，平均 TPOT `11.5 ms`、P95 TPOT `12.2 ms`，平均 `queued_ts → first_token_ts` 为 `1122.5 ms`，P95 为 `2807.4 ms`。该节点的第二张 3090 仍由 `conzone` QEMU/VFIO 使用。由于模型与 Qwen3-30B 不同，该结果只作为 3090 运行链路验证，不参与 4090/5090 性能排名。

## 4. Simulator 对照

使用同一 workload 分别运行固定 P/D Static 和启用资源账本的 CASR。模拟器使用仓库现有 Qwen3-30B profile；该 profile 当前是 RTXPRO6000 的实测 profile，不是 4090/5090 profile，因此对齐结果用于校准和趋势分析，不能当作 4090 的绝对性能预测。

| 对照 | 平均 latency | P95 latency | 平均 TTFT | 平均 TPOT |
|---|---:|---:|---:|---:|
| 真实 vLLM，4×RTX 4090 | `6491.9 ms` | `8509.2 ms` | `1333.9 ms` | `11.3 ms` |
| Simulator Static | `12660.9 ms` | `17859.7 ms` | `57.6 ms` | `28.9 ms` |
| Simulator CASR | `12660.9 ms` | `17859.7 ms` | `57.6 ms` | `28.9 ms` |

本 workload 只有 16 个请求、请求率约 2 req/s，P/D 容量未形成结构瓶颈，因此 CASR 没有触发额外结构动作；该结果说明低负载时控制器保持结构稳定，但不能证明扩缩容收益。

## 5. 异构 baseline/CASR 对照

为放大异构差异，使用仓库的 2×RTX4090 Prefill、1×快 Decode、1×慢 Decode 结构失配配置，比较 Static、CASR greedy 和 CASR LP。该实验是模拟器内的异构资源对照，不代表跨主机真实网络吞吐。

| 指标 | Static | CASR greedy | CASR LP |
|---|---:|---:|---:|
| 请求数 | 80 | 80 | 80 |
| 平均 latency | `2067.042 ms` | `1844.020 ms` | `1755.377 ms` |
| P50 latency | `1616.869 ms` | `1660.863 ms` | `1696.148 ms` |
| P95 latency | `2540.314 ms` | `2414.728 ms` | `2243.537 ms` |
| P99 latency | `2544.257 ms` | `2419.838 ms` | `2256.963 ms` |
| 平均 TTFT | `28.395 ms` | `28.147 ms` | `28.147 ms` |
| 平均 TPOT | `16.052 ms` | `14.298 ms` | `13.600 ms` |
| Prefix hit tokens | 3648 | 3696 | 3696 |
| 快/慢 Decode 请求数 | 40/40 | 60/20 | 71/9 |

相对 Static，greedy 平均 latency 下降约 `10.8%`、P95 下降约 `4.9%`；LP 平均 latency 下降约 `15.1%`、P95 下降约 `11.7%`。CASR 将更多流量路由到快 Decode 实例，同时保留 prefix 命中，体现了 pair cost 和 cache-aware flow 的效果。
