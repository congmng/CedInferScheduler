## 后续部署建议

1. 实验代码、trace、模型缓存和结果优先放在 `10.212.67.167:/mnt/home`、`10.212.67.68:/data/sdb` 和 `10.70.251.46:/` 的专用子目录中。
2. 不在 `10.212.70.196:/data` 写入新实验数据，除非先清理或扩容。
3. 不在 `10.212.67.68:/` 和 `10.212.70.38:/` 根目录放置模型或大规模 trace。
4. 在正式安装 CUDA、vLLM 和 LMCache 前，补充 `10.212.70.38`、`10.212.70.196` 和 `10.70.251.46` 的完整 GPU/驱动核验。
5. 实验自动化脚本应显式使用 `id_casr_cluster`，避免受到用户 SSH agent 中其他身份数量的影响。

## 节点网络核验

2026-09-09 从每台节点向五个 IP 各发送 3 个 ICMP 包。`10.212.*` 内部节点之间的平均 RTT 约为 `0.06–0.47 ms`；到 `10.70.251.46` 的平均 RTT 约为 `26.2–27.9 ms`。因此 CASR 的跨域 pair cost 不应把这两类链路视为同一局域网。

- `10.212.70.196` 当前可用主接口 `ens6f0` 为 `1000Mb/s`。
- `10.70.251.46` 当前可见并启用的 `enp202s0f0` 为 `10000Mb/s`，但该节点 PCI 仍未暴露 A100。
- `10.212.67.68`、`10.212.70.38` 和 `10.212.67.167` 的本轮网卡驱动没有返回可靠的物理速率值，不能把容器虚拟接口显示的 `10000Mb/s` 当作端到端带宽。
- 正式实验应使用 `iperf3` 或应用层 KV 传输测得有效带宽；当前 RTT 结果可先用于区分内网和跨域路径，不能替代吞吐测量。

## 2026-09-09 GPU 修复记录

`10.212.70.196` 的四个 NVIDIA PCI function 为 `10de:2b85`，原先只有第 4 张卡 `41:00.0/1` 被自定义 initramfs 脚本和 `driverctl` 绑定到 `vfio-pci`，同时系统缺少 NVIDIA 驱动模块。已完成以下操作：

- 安装 Ubuntu 推荐的 `nvidia-driver-595-open` `595.91.07`。
- DKMS 已为当前及已安装内核构建成功。
- 将原 `/etc/initramfs-tools/scripts/init-top/vfio-bind-41` 备份到 `/root/casr-backup/vfio-bind-41`。
- 清除 `driverctl` 对 `0000:41:00.0/1` 的覆盖，并在线重新绑定到 `nvidia`/音频驱动。
- 更新全部 initramfs。
- `nvidia-smi` 已验证识别 4 张 RTX 5090，每张显存 `32607 MiB`。

`10.212.70.38` 的 `af:00.0` 由 `nvidia` 驱动管理并可被 `nvidia-smi` 使用；`d8:00.0/1` 由 `vfio-pci` 管理，检查到运行中的 `/usr/bin/qemu-system-x86_64 -name conzone` 正在使用该 PCI 设备。为避免中断已有虚拟机，本次没有解绑该卡；如果后续需要两张 3090，必须先由虚拟机所有者停机并确认资源释放。

`10.70.251.46` 的 root 级核验结果为：机型 `Dell PowerEdge R750`，PCI 设备只有 `Matrox G200eW3`，无 NVIDIA PCI ID、NVIDIA 内核模块、`/dev/nvidia*` 或 NVIDIA 启动日志。该问题位于硬件暴露或宿主机资源分配层，不应在当前系统盲目安装驱动；待管理员在 BMC/BIOS/虚拟化配置中启用 GPU 后，再执行驱动安装和 `nvidia-smi` 验证。
