## Profile 补全

针对统一模型 `Qwen/Qwen3-30B-A3B-Instruct-2507`，使用 profiler 的真实 CUDA layerwise measurement：

- `dtype=bfloat16`、`max_num_batched_tokens=1024`、`max_num_seqs=64`。
- `attention-max-kv=2048`、`measurement-iterations=1`、暂跳过 skew sweep。
- 每种硬件生成 `tp1/tp2/tp4/tp8`，每个 TP 应包含 `dense.csv`、`per_sequence.csv`、`attention.csv` 和 `moe.csv`。
- 已完成并回收到仓库：RTX3090、RTX4090、RTX5090 三套 profile。
- A100 profile 尚未运行，因为其 8 张卡由现有 `mosaic-node-a/b` 服务占用；不在未获确认时停止业务服务。

补全过程中修复了两类兼容问题：

1. vLLM 新版将 `FusedMoE` 重构为 `MoERunner`，MoE 强制路由 hook 现同时支持旧版 `forward_native` 和新版 `forward`/`router.select_experts`。
2. Qwen3 的 `num_key_value_heads=4` 在 TP8 时不能严格整除；profile 分片对 GQA 使用每 rank 至少 1 个 KV head，与实际 TP8 语义一致。

profile 输出位于 `LLMServingSim/profiler/perf/{RTX3090,RTX4090,RTX5090}/Qwen/Qwen3-30B-A3B-Instruct-2507/bf16/`。这些文件来自真实硬件测量，不是按硬件名称复制的模板。

## 当前实验入口

`configs/cluster/casr_real_qwen3_heterogeneous.json` 使用已补全的 RTX5090 TP2 和 RTX4090 TP4 实例，避免把单张显存不足的 3090/5090 当作可承载 56GB 权重的实例。该配置用于 simulator 的结构与调度验证；真实跨主机 P/D 仍需单独部署和测量。

```bash
cd LLMServingSim
```

此前低/高/低负载实验已验证动态 CASR 相比固定 2P 延迟和 GPU-seconds 的变化；profile 补全后将重新运行该矩阵，并把结果写入 `docs/CASR测试报告.md`。
