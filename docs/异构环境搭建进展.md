- `dtype=bfloat16`、`max_num_batched_tokens=1024`、`max_num_seqs=64`。
- `attention-max-kv=2048`、`measurement-iterations=1`、暂跳过 skew sweep；A100 本轮为缩短验证时间使用 `attention-max-kv=1024`。
- 每种硬件生成 `tp1/tp2/tp4/tp8`，每个 TP 应包含 `dense.csv`、`per_sequence.csv`、`attention.csv` 和 `moe.csv`。
- 已完成并回收到仓库：RTX3090、RTX4090、RTX5090 三套 profile。
- A100 已完成 `tp1` 的四类 layerwise profile 并回收到仓库；`tp2` 在 `vLLM 0.26.0` 的 attention 初始化阶段无进展，`tp4/tp8` 尚未完成。A100 的 `mosaic-node-a/b` 业务服务未停止，已完成的 `tp1` 数据可用，未完成 TP 不能用于模拟器精度结论。此前已完成 A100 TP=8 真实 vLLM benchmark，可作为服务可运行性证据，但不能替代 layerwise profile。

- 2026-09-10 使用 `attention-max-kv=256` 的 TP2 attention slice 复测，仍停在 vLLM `0.26.0` 初始化阶段；缩小 profile 网格不能解决该问题。空闲 0/1 号卡已释放，4/5 号卡业务始终未停止。

补全过程中修复了两类兼容问题：

1. vLLM 新版将 `FusedMoE` 重构为 `MoERunner`；同时兼容旧版 `FusedMoE.forward_native`、新版 `MoERunner.forward`，并处理旧版 `FusedMoE` 工厂函数不能用于 `isinstance` 的情况。

## 当前实验入口

`configs/cluster/casr_real_qwen3_heterogeneous.json` 使用已补全的 RTX5090 TP2 和 RTX4090 TP4 实例，避免把单张显存不足的 3090/5090 当作可承载 56GB 权重的实例。该配置用于 simulator 的结构与调度验证；真实跨主机 P/D 仍需单独部署和测量。

当前真实 profile 端到端验证使用 `configs/cluster/casr_real_qwen3_tp4_heterogeneous.json`：4×RTX5090 TP4 Prefill 与 4×RTX4090 TP4 Decode，拓扑为 `[4,3]`。对应入口为 `tests/run_real_qwen3_hetero_comparison.sh`。原混合 TP 配置的总执行 NPU 数为 18，TP2/TP4 不能由同一矩形拓扑表示，配置构建器现会在启动阶段提前拒绝，避免 ASTRA-Sim 静默卡死。

CASR 与基线的统一入口为：

```bash
cd LLMServingSim
bash tests/run_casr_ablation.sh /tmp/casr-current-ablation
```

此前低/高/低负载实验已验证动态 CASR 相比固定 2P 延迟和 GPU-seconds 的变化；profile 补全后将重新运行该矩阵，并把结果写入 `docs/CASR测试报告.md`。

2026-09-10 已完成真实 Qwen3 TP4 异构 smoke test：1 请求完整退出，12-NPU ASTRA-Sim 拓扑生成正确；并完成 16 请求 Static/Greedy/LP 快速矩阵。该配置只有一个 P 与一个 D，三组结果均为平均 latency `5237.092 ms`、P95 `5279.882 ms`，属于 profile 与部署链路验证，不作为 CASR 优势结论。

### 拓扑修复

无 DP 的混合 TP 实例现在按最大 TP 的质因数生成 ASTRA-Sim 维度，并将每个实例的 TP/EP collective 限定到相应的维度前缀。只有当总 NPU 数可整除最大 TP、且每个 TP 是因子前缀积时才接受配置；不满足条件会在启动阶段报错。
